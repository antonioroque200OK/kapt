# Skill: database-migration

Every database schema change in Kapt MUST follow this exact sequence — no exceptions ([HARD-GATE]).
**Never modify a table or create a new one without a corresponding migration file.**

---

## Step 1 — Identify the Change

Clearly state what is changing:
- New table? Which columns, types, constraints, indexes?
- Altering an existing table? Which columns are added/removed/renamed?
- New index or foreign key?
- Data migration required? (i.e., backfilling existing rows)

If the change touches identifiable personal data (photos, faces, biometrics), flag a **LGPD review** before proceeding.

## Step 2 — Check the Last Migration Number

```bash
ls services/sqlc/migration/ | sort | tail -5
```

Identify the highest existing `XXXXXX` prefix to determine the next number.

## Step 3 — Create the Migration File

Create the file at:

```
services/sqlc/migration/XXXXXX_<descriptive-name>.sql
```

Naming rules:
- Zero-pad to 6 digits: `000001`, `000002`, `000003`, etc.
- Use snake_case for the descriptive name.
- Examples: `000004_add_photographer_status.sql`, `000005_create_purchases_table.sql`

The file must contain valid PostgreSQL DDL. Include a header comment:

```sql
-- Migration: XXXXXX_<name>.sql
-- Description: <what this migration does and why>
-- Created: <date>
```

## Step 4 — Run sqlc generate

From the `services/` directory:

```bash
cd services && sqlc generate
```

Verify the command exits without errors. If it fails, fix the SQL before proceeding.

## Step 5 — Verify Generated Code

Check that the following were updated as expected:
- `services/internal/repository/*.sql.go` — generated query files
- `services/internal/repository/db.go` — if new tables were added

Review the diff to confirm no unintended changes were generated:

```bash
git diff services/internal/repository/
```

## Step 6 — Commit Both Together

The migration `.sql` file and all generated Go code MUST be in the **same commit**. Never commit them separately.

```bash
git add services/sqlc/migration/XXXXXX_<name>.sql
git add services/internal/repository/
git commit -m "feat(db): <description of schema change>"
```

Use the appropriate Conventional Commit type:
- `feat(db):` — new table or column supporting a new feature
- `fix(db):` — correcting a schema mistake
- `refactor(db):` — restructuring without behaviour change

## Step 7 — Verify Locally

Run the service locally and confirm:
- Migrations apply cleanly with no errors.
- Existing queries still function.
- New queries return expected results.

```bash
# From the repo root
docker compose up -d
make migrate  # or the equivalent make target
```

---

> ⚠️ **Never** hand-write changes to `*.sql.go` files. These are generated by `sqlc` and will be overwritten. Always edit `.sql` query files in `services/sqlc/query/` and re-run `sqlc generate`.
